# Saturn

Универсальный транслятор, работающий по спецификации синтаксически управляемого определения. На вход подаётся произвольная КС-грамматика вместе с L-атрибутным СУО над ней, на выход — дерево вывода с вычисленными атрибутами и граф зависимостей этих атрибутов.

Разбор входного текста выполняет обобщённый LR-парсер (алгоритм Томиты, вариант 1e), что позволяет принимать грамматики с конфликтами сдвиг-свёртка и локальной неоднозначностью. Грамматика и семантические правила описываются в файле спецификации, пользовательская бизнес-логика выносится в отдельный JavaScript-файл и исполняется через JavaScriptCore.

## Требования

- Swift 6.2 и новее (Swift Package Manager).
- macOS 10.15 и новее. Транслятор использует JavaScriptCore — системный фреймворк Apple, поэтому запуск возможен только на Apple-платформах.
- Graphviz (`dot`) — опционально, чтобы отрисовать граф зависимостей в картинку.

## Архитектура

Пакет состоит из двух целей:

- `saturn-core` — библиотека со всей логикой трансляции (лексер, развёртка сахара, устранение ε-правил, построение таблицы разбора, GLR-парсер, свёртка леса в дерево, вычислитель атрибутов).
- `saturn` — исполняемая цель, точка входа в командной строке.

Конвейер трансляции: лексический анализ → развёртка синтаксического сахара → устранение ε-альтернатив → построение таблицы разбора → GLR-разбор в SPPF → свёртка леса в дерево → вычисление атрибутов → запись результатов.

## Сборка

```
swift build
```

Для запуска тестов:

```
swift test
```

## Запуск

Транслятор принимает один аргумент — путь к директории проекта:

```
swift run saturn --path /path/to/project
```

В указанной директории должны лежать входные файлы (см. ниже). Результаты записываются туда же. Атрибуты аксиомы дополнительно печатаются в консоль.

### Входные файлы

| Файл | Обязателен | Назначение |
|------|:----------:|------------|
| `configuration.spec` | да | Грамматика и семантические правила в терминах СУО. |
| `input.txt` | да | Текст, который нужно оттранслировать. |
| `semantics.js` | нет | Пользовательские типы, константы и функции, вызываемые из семантических правил. |

Файл `configuration.spec` отвечает за то, **что** вычислять: терминалы и нетерминалы, продукции грамматики, уравнения для синтезированных и наследуемых атрибутов. Файл `semantics.js` отвечает за то, **как**: реализацию пользовательских структур и вспомогательных функций. Если семантические правила не вызывают внешнюю логику, `semantics.js` можно не создавать.

### Выходные файлы

| Файл | Содержимое |
|------|------------|
| `tree.json` | Дерево вывода с атрибутами в каждом узле. |
| `graph.dot` | Граф зависимостей атрибутов в формате Graphviz. |

## Пример

Минимальная директория проекта для грамматики объявлений:

`configuration.spec`
```
Program = %rep( Decl )
Decl    = Type id [ EQ num ] %rep[ COMMA id [ EQ num ] ]
Type    = kwInt | kwFloat
```

`input.txt`
```
int x = 5, y
```

Запуск:

```
swift run saturn --path ./examples/declarations
```

После запуска в директории появятся `tree.json` и `graph.dot`.

## Просмотр результатов

Отрисовать граф зависимостей в картинку:

```
dot -Tpng graph.dot -o graph.png
```

Посмотреть дерево в читаемом виде:

```
cat tree.json | python3 -m json.tool
```

## Ограничения

- Проверяются только L-атрибутные определения. Спецификации вне класса L транслятор статически не отлавливает — корректность вычисления для них не гарантируется, ответственность лежит на авторе спецификации.
- Граф зависимостей строится для отчёта и не управляет порядком вычисления.
- Пустой допустимый вход для обнуляемой аксиомы дерева не порождает: разбор завершается явной ошибкой, а не аварией.
